# W-30 聊天体验批（消息时间 / 收藏 / 翻译 / 语音输入 / 代码高亮）

## 为什么做这批

四家对照里 RikkaHub 在「聊天体验」上领先一截，但这类功能不影响"能不能把事办成"，
所以一直排在能力面之后。P1 只剩并行子代理（成本高）时，这批是用户感知最直接的补位。

## 交付了什么

| 功能 | 交互 | 落点 |
|---|---|---|
| 消息时间 | 气泡下方小字：今天 `HH:mm` / `昨天 HH:mm` / `周X HH:mm` / `M月d日` | `ChatTime` |
| 收藏 | 消息下方「⋯」→ 收藏；设置页 → 收藏 查看/复制/删除/清空 | `BookmarkStore` + `BookmarkScreen` |
| 翻译 | 同一菜单 → 翻译；译文贴在原气泡下方，可收起 | `TranslateLogic` + `TranslateUi` |
| 语音输入 | 输入框为空时右侧麦克风 → 系统识别 → 追加到输入框 | `SpeechLogic` |
| 代码高亮 | 助手消息里的围栏代码块按语言着色（复用编辑器词法器） | `SyntaxHighlighter.normalizeLanguage` |

## 关键设计取舍

**时间戳为什么不显示"刚刚"**：聊天里"刚刚"只会出现在最后两分钟，之后突然跳成时间，
信息密度低且抖动。直接给时钟时间，一眼知道"这是半小时前还是昨晚"。

**为什么用 UTC 做纯函数**：`ChatTime` 要不依赖 `java.time`/时区才能被 harness 直接断言。
展示粒度是"今天/昨天/日期"，UTC 与本地最多差一天，可接受；需要绝对时刻的场景用 `precise()`。
**已知限制如实记**：跨时区/接近午夜时，`今天/昨天` 的判断可能偏一天。

**收藏为什么存快照**：会话会被删除、轮次会被「从此处删除」截断，引用会变死链。
收藏的语义是"这条内容我要留着"，所以存正文（单条上限 2 万字）+ 来源会话标题 + 原时间。

**翻译为什么不写进会话**：译文是临时视图。写进 `MsgRecord` 会污染下一轮上下文
（模型会把译文当自己说过的话），也会让「重新生成」拿到混合内容。因此只放内存 map，
切会话即清空（下标全变，串到别的消息上比不显示更糟）。

**语音为什么借系统识别器**：自己录音要申请 `RECORD_AUDIO`、处理采样率/降噪/静音检测，
收益远不如直接用各家 ROM 自带的识别服务（`RecognizerIntent`，不需要任何权限声明）。
代价：部分精简 ROM 没有识别服务 → 如实 Toast「本机没有可用的语音识别服务」。

**代码高亮不引库**：复用 W-27 的 60 行词法器，只加 `normalizeLanguage` 做别名归一
（`kt`/`py`/`bash`/`c++`…）。不认识的语言返回 null = 纯文本，不猜关键字。

## 已知未做

- 收藏**不支持搜索**：上限 500 条，滚动即可（收藏是精选，不是归档）
- 翻译目标语言固定中文（`TranslateLogic.LANGUAGES` 已备多语言，UI 没给选择器）
- 语音输入不支持长按录音/实时转写（只做"点一下说一句"）
- 消息时间不随分钟自动刷新（打开页面时算一次）
