# SKIP 登记册 —— gate.sh 门禁 6 的判据（R-17）
#
# 为什么需要这份文件：
#   SKIP 是本项目唯一「什么都不验证也算过」的状态。门禁 5 卡 PASS 下限，能挡住
#   「大面积 SKIP」，但挡不住**新增**——新加一个 runner，第一行就 `exit 3`，
#   PASS 总数不变，门禁 5 照样绿。于是这个 harness 从诞生那天起就是零覆盖，
#   而它比「断言失败」隐蔽得多：失败会红，消失只会让分母变小。
#
# 收录条件（三条都要满足）：
#   ① runner 确实写了 `KS_HARNESS_SKIP`，且理由里的缺件路径**真的不存在**
#      （run-all 会 stat 它，不成立当场判 FAIL —— 见 run-all.sh 的 skip_claim_is_true）；
#   ② 缺的东西不是这个仓库能自己产出的（否则就该补上，不是登记）；
#   ③ 写清「缺什么」与「哪个环境能满足」——没有后者的登记项，就是永久豁免。
#
# 移除条件：环境补齐后它会自己变 PASS，门禁 6 会提示「N 条本轮没有 SKIP」
#   ——这是「只提示、不判 FAIL」（见 gate.sh 门禁 6 末段）。这类「登记了但本轮
#   没 SKIP」的条目是跨环境白名单：换到缺依赖的机器上它们会重新 SKIP，删掉
#   反而会触发「SKIP 未登记」FAIL。只有当所有目标环境都常备该依赖时才删行，
#   并把下面的上限数字一起调小；单台机器偶尔补齐不构成删除理由。
#
# 条目上限：42
#
# 只减不增：新增 harness 必须能在本机真跑。实在只能 SKIP，就显式改这个数字——
# 让「又多了一个零覆盖的 harness」成为一次需要人点头的决定，而不是一次
# 顺手 `echo skip` 的事故。
