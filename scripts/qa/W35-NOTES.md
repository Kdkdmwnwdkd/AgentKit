# W-35 整仓克隆（github_clone）

## 缺口

W-32~W-34 解决了"改完能提交/看差异"，但前提是**工作区里已经有那份代码**。
要把别人的仓库拿来读/改，之前只能手动下载解压。

## 实现：codeload zip，不走 API

| 方案 | 判断 |
|---|---|
| 逐文件调 contents API | 仓库 364 个文件 = 364 次请求，一次 clone 就打掉一大半配额 |
| **codeload zip**（本批） | 一次请求拿整包，**不消耗 API 额度** |
| 真 git clone | 手机端没有 git 二进制 |

失败时回退 `gh-proxy` 镜像（与 HF 镜像、APK 加速同一套"国内可用"纪律）。

## 安全（Zip Slip 是这类功能的经典漏洞）

每个条目名都过 `CloneLogic.safeEntryName`：
- `..` 段、绝对路径、连续斜杠（空段）、`.git/` 开头 → 拒绝
- 先剥 GitHub zip 的顶层目录（`Repo-main/`）
- 单文件 20MB / 总量 80MB / 条目 1500 个三重上限
- **超限即中止并删掉已解压的部分**——不留"看起来克隆了其实只来了一半"的半成品

## 为什么默认解压到子目录

工作区里有用户/模型自己的文件，铺到根上会盖掉它们。
默认 `repo-<仓库名>`（可指定 `dir`），子目录是隔离带。

## harness 抓到的 2 个真 bug

1. **`/etc/passwd` 会漏过检查**：先剥顶层目录，斜杠被当成顶层分隔符削掉，
   绝对路径就变成了相对路径。→ 绝对路径检查移到剥顶层目录**之前**。

2. **目标目录的绝对路径检查失效**：原实现先 `trim('/')` 再判 `startsWith("/")`——
   斜杠已经被 trim 掉了，条件永远不成立。→ 同样调整判断顺序。

这两个都是"顺序错了"的同类错误，各自都在 harness 里被抓到（不是靠肉眼）。

## 真实仓库对拍

下载 AgentKit 自己的仓库 zip（5.8MB）跑一遍规则：
- 435 个条目，**434 个通过**，唯一被拒的是顶层目录条目 `AgentKit-main/`
  （正确——target 目录本身就是它，不需要再建一层）
- 条目数远低于 1500 上限，包体远低于 60MB 上限
- "zip 一定有顶层目录"的假设成立

## 验证

- harness **15/15**（条目名 9 + 目录命名 5 + 常量 1）
- 既有 harness：27/25/14/9/12/13/18/16/34/18/24/21/13 全无回归
- 反验断言：9 条池条目 + 4 条文案

## 已知限制

- **不是真 clone**：没有 `.git` 目录，无法在本地做 git 历史/分支切换。
  语义是"下载这份代码"，工具名沿用 clone 是因为用户心智里这就是 clone。
- **只支持公开仓库**（codeload 下载不带 Authorization）。
- **上限会拒绝大仓库**（80MB / 1500 文件）：如实报错并建议改用 `github_diff` 逐文件看。
