# W-28 批次记录：@提及文件 + 工作区绑定会话

> 依据：缺口 #27（@提及文件）、#75（工作区绑定会话）。两者同属"上下文管理"，一起做。

## 一、@提及文件（#27）

### 交互
1. 输入框打 `@`（行首或空格后）→ 输入栏上方弹出**横滑文件建议**；
2. 继续打字符做模糊匹配（前缀 > 目录内文件名前缀 > 包含 > 子序列）；
3. 点一个 → 输入框里的 `@关键词` 替换成 `@相对路径 `（补尾空格，方便继续写）。

### 发送时
`@path` 提到的文件内容被读出来，拼成 `[被提及的文件：path]` 块放在「用户当前请求」之前。
预算：**单文件 ≤ 8KB、总量 ≤ 24KB**，超出截断并注明——不让一次 @ 把上下文吃满。
读取失败的文件**跳过**（一个文件名写错不阻断发送）。

### 边界
- 邮箱 `a@b.com` 里的 `@` 不触发（`@` 前必须是行首/空白）；
- `@张三` 不算文件（必须带点或斜杠才认）；
- 关键词遇空格即结束（打完文件继续写句子不会被吞）。

## 二、工作区绑定会话（#75）

### 交互
抽屉里长按会话 → 菜单新增「绑定项目目录」→ 列出工作区内的目录（首项「不绑定」）。

### 效果
绑定的目录下若有 `AGENTS.md` / `README.md`（依次尝试），内容作为
`[项目规则：path]` 块注入**每轮请求的前缀最前面**，上限 4KB。

为什么不放进每轮 user 消息：项目规则是**稳定上下文**，放前缀会和普通内容一起被
ContextBudget 压缩；单独成段更容易被模型遵守。

### 安全边界
只列**工作区内的目录**——绑定不会打开任意磁盘路径，Agent 仍只能读写工作区。

## 四、已知边界

- 建议条只认**文本末尾**的提及（用户一般就在末尾打 @）；在句子中间补 @ 不会弹。
  改为光标感知需要把输入框状态升级成 TextFieldValue——影响面大，暂不做。
- 绑定的目录是"上下文提示"，不是权限边界：Agent 仍可读写工作区其他位置。
- `AGENTS.md` 不存在时回退 `README.md` / `README.txt`；都没有则无项目规则。
