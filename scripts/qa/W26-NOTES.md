# W-26 批次记录：任务模型分离 + 备份补 Key 池

> 依据：缺口 #48（任务模型分离）、#33（重新生成会话标题）、W-22 遗留（备份漏备用 Key 池）。

## 一、AI 会话标题（#33）

### 现状
标题是**截取首条消息前 20 字**——"帮我整理一下下载目录里的重复文件，还有…"直接变成标题，
抽屉列表里一屏全是半句话。

### 现在
首轮对话后**异步**用「任务模型」生成 6~12 字标题：
- 只在标题仍是默认值/截取文本时生成（用户手动改过的不覆盖）；
- 无信息量开场（"你好""在吗""hi""😀😀"）**不触发**，省一次调用；
- 失败静默（标题不是主流程）；
- 清洗吃掉模型的脏输出：引号、「标题：」前缀、句末标点、第二行解释、超长截断。
  规则在 `TitleLogic`（纯函数，harness 12/12 里的 8 条）。

## 二、任务模型分离（#48）

设置页新增「任务模型」：
- 默认**跟随主配置**；
- 可选任意已有档案（比如聊天用 DeepSeek V4，任务模型用便宜的 flash）。

轻量任务（当前是标题生成，后续记忆抽取/摘要也走这里）用任务模型，聊天主体不变。
实现：`buildTaskClient()` 优先取任务档案，档案被删则回退主配置。

**取舍**：任务请求**不走** Key 池切换——轻量任务失败就放弃，不占用备用 Key 的冷却额度。

## 三、备份补 Key 池（W-22 遗留）

- `BackupArchive` 新增可选成员 `keypool.json`（白名单、create 参数、ReadResult 均加）；
- 导出：`KeyPoolStore.exportAll()` → `{profileId:[{id,label,key}]}`；
- 恢复：`importAll()` 覆盖同档案的池；
- **老备份（无该成员）读回 null，恢复时保持现状**——不破坏既有用户数据；
- harness 验证往返 + 老包兼容 + 坏包仍被拒。

## 五、已知边界

- 标题生成消耗一次模型调用（首轮最多一次）；关掉方式：暂未单独设开关，
  如需可把任务模型选成一个极便宜的模型，成本可忽略。
- 任务模型目前只服务于标题生成；记忆抽取仍是纯规则（不调模型，零成本）。
- 备份里的钥匙是**明文**（与 config.json 里的 apiKey 一致）；备份文件本身应妥善保管。
