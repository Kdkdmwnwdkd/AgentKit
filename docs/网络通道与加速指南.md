# AgentKit 网络通道与加速指南

> **给下一个会话的自己看。** 沙箱环境对 GitHub 的访问是**被劫持**的，不按这份文档走会白白浪费几十分钟。
> 最后更新：2026-10-19。每次踩到新坑请回来更新本文。

## 一句话记住这三条

1. **下载一律走 `gh-proxy.com`** —— 别用 `api.github.com` 的 artifact 接口
2. **写（提交）一律走 MCP** —— `mcporter call github.push_files`
3. **超过 100KB 的文件走 REST API** —— MCP 会报 `argument list too long`

---

## 一、沙盒限制：现象与根因

**现象**：沙箱里 `curl https://api.github.com/...` 返回 `000`（无应答），`git clone` 挂起（TCP 连上但不传数据）。

**根因**：出网代理把 `api.github.com` 的 DNS 解析到 **`198.18.0.x` 保留网段**（不可路由），请求出不去。

**但并非所有 GitHub 域名都被劫持**：

| 域名 | 状态 |
|---|---|
| `api.github.com` | ❌ 被劫持（DNS → 198.18.0.x） |
| `github.com` / `codeload.github.com` | ⚠️ 解析到真实 IP，但**极慢**（~72 KB/s），大文件会超时 |
| `api.githubcopilot.com`（MCP 端点） | ✅ **不在拦截名单**，真实 IP 140.82.113.21 |
| `gh-proxy.com`（镜像） | ✅ **快**（~18 MB/s） |

## 二、三条可用通道

### 通道 A：MCP（写 + 读，首选）

端点 `https://api.githubcopilot.com/mcp/`，不在拦截名单。

```bash
# 注册（沙箱重置后需要重做，见第四节）
mcporter config add github "https://api.githubcopilot.com/mcp/" \
  --transport http --header "Authorization=Bearer <PAT>" --scope home
mcporter list github                     # 能列出工具即通

# 读（返回内容 + sha，更新已存在文件时 sha 必填）
mcporter call github.get_file_contents owner=Kdkdmwnwdkd repo=AgentKit path=docs/x.md ref=main

# 写（一次提交多个文件，3 秒完成，零重试）
mcporter call github.push_files owner=Kdkdmwnwdkd repo=AgentKit branch=main \
  message="..." files='[{"path":"docs/x.md","content":"..."}]'
```

实测：一次提交 **3 秒**，而 `git push` 直连要 135 秒超时重试 2~6 次。

### 通道 B：REST API（大文件写，绕开参数长度限制）

`mcporter` 通过命令行传参，受 `ARG_MAX` 限制——**单文件 >100KB 会报 `argument list too long`**
（例如 `ChatViewModel.kt` 156KB、`ChatScreen.kt` 122KB）。改用 curl + REST：

```bash
export GH_TOKEN=$(cat /tmp/.ghpat)

# 1) 取当前 sha（已存在的文件必须提供，否则 422）
SHA=$(curl -s -H "Authorization: token $GH_TOKEN" \
  "https://api.github.com/repos/Kdkdmwnwdkd/AgentKit/contents/<路径>?ref=main" \
  | python3 -c "import json,sys; print(json.load(sys.stdin)['sha'])")

# 2) 构造 payload（base64，写在文件里，不进命令行）
python3 -c "
import json, base64
c = open('<本地路径>','rb').read()
open('/tmp/push.json','w').write(json.dumps({
  'message':'<提交信息>',
  'content': base64.b64encode(c).decode(),
  'sha': '$SHA',
  'branch':'main'
}))"

# 3) PUT
curl -s -X PUT -H "Authorization: token $GH_TOKEN" \
  --data @/tmp/push.json \
  "https://api.github.com/repos/Kdkdmwnwdkd/AgentKit/contents/<路径>"
```

**注意**：REST 走 `api.github.com`，但**带 Authorization 头时可用**（被劫持的是匿名 DNS 路径，
实际 curl 带 token 走通常能通；不通就退回 MCP 分块或多文件分次）。

### 通道 C：gh-proxy 镜像（只读，用于同步与下载）

```bash
# git 同步（秒回，只读）
git fetch https://gh-proxy.com/https://github.com/Kdkdmwnwdkd/AgentKit.git main
git reset --hard FETCH_HEAD        # 对齐本地（MCP 提交会导致本地与远端分叉）

# 无网时手动对齐跟踪引用
git update-ref refs/remotes/origin/main <sha>
```

⚠️ **镜像只读**：`git push` 走镜像会报 `No anonymous write access`（镜像不转发鉴权头）。
⚠️ **不要带 Authorization 头**（带了镜像反而失效/变慢）。

### 兜底：git push 直连

可用但极不稳定（单次超时可达 135 秒，常需 2~6 次重试）。**优先 MCP，这个只作兜底。**

```bash
GIT_ASKPASS=/tmp/git-askpass.sh timeout 420 git push origin main
```

**凭据位置**：PAT 存 `/tmp/.ghpat`；`GIT_ASKPASS=/tmp/git-askpass.sh`。

## 三、加速下载（这块差别是 78 秒 vs 30 分钟）

**血的教训**：用 `api.github.com` 的 artifact 接口下 30MB 的 APK，实测 ~35KB/s，
**跑了 30 分钟没下完**，后台任务还被 SIGKILL。走镜像 **78 秒**。

```bash
# APK 加速直链（latest = CI 每次构建自动发的 Release tag，永远指向最新包）
curl -sL --max-time 300 -o app-debug.apk \
  "https://gh-proxy.com/https://github.com/Kdkdmwnwdkd/AgentKit/releases/download/latest/app-debug.apk"

# 整仓 tarball（~18 MB/s，用于拉参照仓库源码）
https://gh-proxy.com/https://github.com/<owner>/<repo>/archive/refs/heads/<branch>.tar.gz

# 仓库 zip（codeload，下载整仓克隆用）
https://gh-proxy.com/https://codeload.github.com/Kdkdmwnwdkd/AgentKit/zip/refs/heads/main
```

**备用镜像**（主链打不开时换）：

```
https://ghfast.top/https://github.com/...
https://gh-proxy.net/https://github.com/...
```

**不要用**：`codeload.github.com` 直连（只有 72KB/s，大仓库超时）、`git clone` 直连（挂起）。

## 四、沙箱重置后的 MCP 恢复（必做第一步）

沙箱重置会清掉 `/root/.codebuddy/.mcp.json` 里的 github 条目（会只剩 space-library），
导致又退回「git push 硬重试」。**每次新会话先跑这个**：

```bash
# 1) 注册到 mcporter（CLI 直调，不需要重启会话）
mcporter config add github "https://api.githubcopilot.com/mcp/" \
  --transport http --header "Authorization=Bearer <PAT>" --scope home
mcporter list github
```

同时把条目写回 `/root/.codebuddy/.mcp.json`（供内置插件下个会话加载）：

```json
"github": {
  "type": "http",
  "url": "https://api.githubcopilot.com/mcp/",
  "headers": { "Authorization": "Bearer <PAT>" },
  "transparent_proxy": true
}
```

PAT 是用户自建 classic token，需勾选 `repo` 权限。**连接器的 OAuth token 权限不足会 403。**

## 五、按文件大小选推送方式

| 文件 | 方式 |
|---|---|
| 单个 <100KB | `mcporter call github.push_files`（一次可带多个） |
| 单个 >100KB | REST API（curl + base64 payload 文件） |
| 多个文件，总量大 | 分批：**小文件走 MCP 一批，大文件逐个走 REST** |

实测参考大小：`ChatViewModel.kt` 156KB、`ChatScreen.kt` 122KB、`AppScaffold.kt` 63KB、
`SettingsScreen.kt` 31KB、`ConversationStore.kt` 28KB。

## 六、推送后的验证流程（五道门）

```bash
export GH_TOKEN=$(cat /tmp/.ghpat)

# 1) 查 CI（等它跑完，~5~6 分钟）
RUN=$(gh run list --limit 1 --json databaseId -q '.[0].databaseId')
gh run watch $RUN --exit-status

# 2) 失败就看日志（按日志定位，不要猜）
gh run view $RUN --log 2>&1 | grep "e: file" | head -8

# 3) 绿了下 APK 做 dex 反验
curl -sL --max-time 300 -o app-debug.apk \
  "https://gh-proxy.com/https://github.com/Kdkdmwnwdkd/AgentKit/releases/download/latest/app-debug.apk"
python3 scripts/qa/verify-apk-features.py app-debug.apk
```

`gh` 命令走 `api.github.com`——**带 `GH_TOKEN` 时通常可用**；不通就用 WebFetch 查：
`https://api.github.com/repos/Kdkdmwnwdkd/AgentKit/actions/runs?t=<时间戳>`
（⚠️ WebFetch 有 15 分钟缓存，复核状态时加 `?t=<时间戳>` 绕过）

## 七、踩过的坑（别再踩）

1. **MCP 提交会让本地与远端分叉** —— MCP/REST 提交不经过本地 git，之后 `git push` 会被拒。
   解决：`git fetch ... && git reset --hard FETCH_HEAD` 重新对齐。

2. **`mcporter` 参数长度** —— 见第五节，`argument list too long` 就是这个。

3. **镜像带 Authorization 头会失效** —— 下载/同步一律不带。

4. **下载别用 artifact 接口** —— 见第三节。

5. **`git clone` 直连会挂起** —— TCP 连上不传数据，重试 5 次均失败，别浪费时间。

6. **分支名**：`rikkahub` 默认分支是 `master` 不是 `main`；其余是 `main`。
   codeload 用 HEAD 探分支，404 即分支名错。

7. **本地编译不可用** —— 沙箱无 AGP 缓存（`/root/.gradle/caches` 空），
   `gradle assembleDebug` 起不来。**编译验证交给 CI**，本地只跑纯 JVM harness。

- [ ] `mcporter list github` 能列出工具（否则先做第四节恢复）

- [ ] 推完查 CI，失败看日志定位（不猜）
