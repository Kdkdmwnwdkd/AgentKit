## 三、拉取与检索方式（实测可用）

```bash
# 拉 tarball（gh-proxy，秒级；不要带 Authorization）
curl -fL "https://gh-proxy.com/https://github.com/<owner>/<repo>/archive/refs/heads/<branch>.tar.gz" -o /tmp/refs/x.tgz
tar xzf /tmp/refs/x.tgz -C /tmp/refs

# 找配对/调试实现（关键词）
grep -ril "spake\|adb pair\|AdbPairing\|wireless debug\|exportKeyingMaterial" /tmp/refs/<repo>/app/src
```

## 四、阅读清单（每家按此顺序）

1. **配对**：是否有 `Spake2`/`pairing` 类；用的是 native 库、JNI，还是纯 Kotlin；
2. **连接**：`CNXN/AUTH/OPEN/WRTE` 状态机；是否复用 `adb` 二进制；
3. **Shell**：命令执行、输出分流、退出码、超时与截断；
4. **权限引导**：无线调试的跳转、配对码输入、失败文案；
5. **降级**：配对不可用时是否回退无障碍，如何提示。

## 四之补：四家「调试权限」实现（2026-10-17 实证）

| 参考 | 提权方式 | 关键文件 |
|---|---|---|
| **Operit** | **Shizuku**（内置 Shizuku 安装器 + 引导） | `core/tools/system/ShizukuAuthorizer.kt`、`ShizukuInstaller.kt`、`DebuggerShellExecutor.kt` |
| **AiCode** | **Shizuku** | `domain/shizuku/ShizukuManager.kt`、`ShizukuShellService.kt`、`tool/shizuku/ShizukuTool.kt` |
| **Coomi** | **Shizuku + libsu（root）** | `CoomiService.java` 等 4 处 |
| **RikkaHub** | 无提权通道（仅 Runtime 一次） | — |

**结论（重要）**：
1. 四家**没有一家**在 App 内实现 adb 无线配对；它们的「调试权限」= 让用户装 **Shizuku**，
   Operit 甚至把 Shizuku 安装包内置、用向导教用户「在 Shizuku 里选『通过无线调试启动』」。
2. 你看到的「后台清文件、不跳屏」是 **Shizuku（shell uid 2000）** 干的，不是 Operit 自己。
3. 我们「一个 App、不装第二个」的目标**高于这四家**——没有现成 Kotlin 配对实现可参考，
   SPAKE2 只能自研。这是差异化，也是成本。

## 五、当前结论（随阅读更新）

- AOSP 配对 = 普通 TLS + `exportKeyingMaterial("adb-label\0", 64B)` + SPAKE2 + AES/GCM，
  **不是 TLS-PSK**；Android 12+ 有公开 API，纯 Kotlin 可行。
- 我们已完成：协议层（14/14）、连接/AUTH/执行（5/5，假 adbd）、配对骨架（7/7）。
- **唯一缺口**：SPAKE2 算法（BoringSSL `spake25519`）。在读到可信参考前不动手。
