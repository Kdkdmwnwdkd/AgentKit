# W-73：分词通了，接着暴露的是「慢且看不见」

1.437 装上去之后，真机日志终于越过了分词那一关：

```
12:27:44.568  → 请求 model=qwen2.5-3b-instruct-q4_k_m.gguf
12:33:47.127  用户请求停止运行          ← 中间 6 分 2 秒，一行输出都没有
```

这不是卡死，是**在算**——但用户看不到任何东西，体感等于死机。所以这一版同时做两件事：
把「等待」砍短，把「在动」显示出来。

## 一、为什么会等这么久

| 环节 | 原因 |
|---|---|
| prefill | prompt 2947 字符 ≈ 1800 token，3B Q4 在手机 CPU 上十几 tok/s → 1~3 分钟 |
| 生成上限 | `DEFAULT_MAX_TOKENS = 2048`。小模型一旦不吐结束符（很常见），就要吐满 2048 个 token 才停；按 3~5 tok/s 算正好 7~11 分钟 |
| 线程 | `n_threads_batch` 也钉在 4（大核数）。prefill 是纯算力活，小核闲着 |
| 重复 | 采样链里没有重复惩罚，3B 中文短对话容易「同一句循环」，越循环越停不下来 |

四个叠在一起，就是「发个你好，等 500 秒」。

## 二、改了什么

**native（`llama-jni.cpp`）**

1. `n_threads_batch` = `max(n_threads, min(硬件核数, 8))`：生成仍只用大核（内存带宽受限，多线程无益），prefill 拉满可用核。
2. `n_batch` 2048 → 512：不会变慢（`llama_decode` 内部本来就按 `n_ubatch=512` 分趟算），但换来「每 512 token 一行进度」和「点停止最迟 512 token 后生效」。
3. 采样链加重复惩罚 `penalties(64, 1.15, 0, 0)`：专治「一直重复一句」和不吐结束符。
4. 每块 prefill 打 `prefill 进度：x / y token，N ms（z tok/s）`；每 32 个生成 token 打 `生成进度：…`。
5. prefill 循环里检查停止标志——之前是不可中断的黑盒。

**Kotlin（`LocalLlamaClient`）**

1. 生成线程不再被 `join()` 干等：改成 1.5 秒轮询，把 native 新增的进度行实时转进 App 运行日志。**用户中途点停止，日志里也留得下「算到第几个 token」**。
2. 卡死看门狗：180 秒没有首字、也没有任何新进度行 → 中止并报「这个模型对当前设备太重，换 0.5b/1.5b」。
3. 工具调用 JSON 不再无限憋：超过 400 字符还没结束就当普通文本流式放行。之前首字符是 `{` 就整段憋住，界面几分钟一个字都没有。
4. 用户主动停止、且还没出字 → 不再抛「空文本」错误（停止不是故障）。
5. 工具协议提示词瘦身：描述截 48 字、参数只留 `名字:类型`。prompt 里最长的一段，直接影响首字延迟。

**设置**

`DEFAULT_MAX_TOKENS` 2048 → 512。云端 API 无所谓，本地这是「一张 8 分钟的空头支票」。

## 三、这一版之后应该看到什么

运行日志（设置 → 数据 → 运行日志）里 `LocalLlama` 会有：

```
开始生成：prompt 2xxx 字符，上限 512 token，线程 4
prefill 进度：512 / 1800 token，28000 ms（18.3 tok/s）
prefill 进度：1024 / 1800 token，55000 ms（18.6 tok/s）
prefill 完成：复用 0 / 共 1800 token，补算 1800，耗时 96000 ms（18.8 tok/s）
生成进度：32 token / 78 字符，9000 ms（3.6 tok/s）
native 摘要｜…
```

`prefill … tok/s` 和 `生成 … tok/s` 这两个数就是这台设备的真实水平：
prefill 十几、生成三五，是 3B 的常态；想要「秒回」，只有换 0.5B/1.5B。
