# W-70：本地模型「配好了却用不了」

真机反馈（2026-10-28，录屏 + 运行日志）：

```
10:15:20 [LocalLlama] 已导入本地模型 qwen2.5-3b-instruct-q4_k_m.gguf（2007 MB）
10:16:05 [Chat] 用户发送：？
10:16:05 [LLM] → 端点 endpoint=https://api.agnes-ai.cn/v1/chat/completions model=agnes-3.0-flash
```

用户的操作是完整的：切到「本地模式」档案 → 配置页里把供应商点成「本地模型（内置）」→
测试连接显示「连接正常」→ 切到「本地模型」页签确认模型在里面 → 回对话页发消息。

结果请求打到了 Agnes，本地推理**一次都没启动**（日志里没有任何 `加载模型` 或
`llama-jni` 记录）。用户看到的结论自然是「本地模型没弄好」。

## 根因：编辑态和已生效配置是两套值

配置页的 `baseUrl` / `apiKey` / `model` / `providerId` 都是 `remember(config)` 的**编辑态**，
只有点「保存」才走 `updateConfig` 写回。而「保存」按钮只在「模型」页签的底部——
用户一旦切到「本地模型」页签选模型文件，就再也看不见它了。

中间还有两个把人带偏的信号：

1. **测试连接用的是编辑态**。它按编辑态造 client，所以本地模式测出来是「连接正常 ·
   端点 本地推理 · llama.cpp」，绿色卡片一看就像已经生效了。
2. **对话页顶栏的就绪判定只看云端三要素**（`baseUrl && apiKey && model` 非空）。
   本地模式这三项本来就该是空的，于是顶栏在切到本地后仍然显示「模型未配置」。

## 改动

| 位置 | 改了什么 | 为什么 |
|---|---|---|
| `ChatViewModel.setActiveLocalModel` | 选中本地模型文件时，**立即**把当前档案的 provider 切成 `local-llama` 并落盘 | 「点了这个模型」= 「要用它对话」，不该还要求用户去另一个页签点保存 |
| `ChatViewModel.modelReady` | 新增单一口径的就绪判定：本地看「有没有选模型文件」，云端看三要素 | 原先三处各写一遍云端判定，本地模式全被误判成未配置 |
| `ChatScreen` / `AppScaffold`（两处） | 全部改用 `vm.modelReady` | 顶栏指示条、首启权限引导、聚光灯引导三处统一 |
| `ChatScreen` 顶栏 | 本地模式下显示「模型文件名 · 设备内推理」 | 原来显示 `agnes-3.0-flash`，用户以为还在用云端 |
| `ModelConfigScreen` | 未保存时在**任意页签**顶部显示「改动还没保存，对话仍用旧配置 + 保存」 | 保存入口不再只存在于一个页签的底部 |
| `ModelConfigScreen` | 切到本地模式时**只清 Base URL、保留 API Key** | W-23 当年连 Key 一起清，用户切回云端得重填 48 位 Secret |
| `ChatViewModel.buildMainClient` | 每次取 client 打一行 `主客户端 provider=… model=… base=…` | 下次再出现「切了没用」，日志能自证走的是谁 |

## 不做的事

- **不做成「一切换供应商就自动保存」**：用户可能只是想看看本地有哪些模型，
  或者正在编辑 Base URL 时手滑点了供应商。改成「选模型文件才落盘」——
  那是一个明确到不可能误触的动作。
- **不清空 API Key**（同上）：本地客户端不读这两个字段，留着无害且让切换可逆。

## 验证

1. 配置页切到「本地模型（内置）」，**不点保存**直接切到「本地模型」页签
   → 顶部应出现「改动还没保存」提示条
2. 在「本地模型」页签点一下模型文件
   → 回对话页，顶栏应显示「<文件名> · 设备内推理」，而不是某个云端模型名
3. 发一句话
   → 运行日志应出现 `[LocalLlama] 加载模型 …`，且**没有** `[LLM] → 端点 endpoint=https://…`
   → 再出现 `[Chat] 主客户端 provider=local-llama model=… base=—`
