# W-68 设置页信息架构：同类合并 + 调试通道归位

## 用户的原话

> 「我的意思是，比如外面他都有一个 Shizuku 和无线调试，但是权限里面有一个，为什么这两个要放在外面呢，
> 我意思差不多的就组合在一起，不是说只有和通知差不多的才放在一起，那些意思差不多都放在一起。」

两件事：

1. **同类项被拆到两个页面**：Shizuku 在权限中心有一行（带授权动作），无线调试在设置页另起一组。
   两条路都是「不装无障碍、靠 uid 2000 操作界面」，用户得在两个页面各看一半，自己拼。
2. **小组太多**：设置页 10 张卡片，其中 5 张只装一行（外观 / 通知 / 任务执行 / 帮助 / 关于）。
   卡片密度一高，页面读起来是「一串分隔条」而不是「几件事」。

## 改了什么

### 一、调试通道收进权限中心

- 新增 `ui/AdbChannelSection.kt`：无线调试的配对、测试连接、断开清除，整块从设置页搬过来。
- `ui/PermissionsScreen.kt` 在「调试通道怎么开」之后调用它。现在两条调试通道在同一页：
  Shizuku 在权限列表里（带四态文案 + 去授权按钮），无线调试在下方的分区里。
- 设置页删掉整个「调试通道」分区，包括 Shizuku 那行状态说明——它和权限列表里的 Shizuku 行
  说的是同一件事，留两处只会让人怀疑「是不是要各开一次」。

### 二、10 组收成 6 组

| 现在 | 内容 | 合并自 |
|---|---|---|
| 轻量任务 | 跟随主配置 + 各 profile | 原「轻量任务模型」（移到 hero 卡之后，语义连续） |
| 通用 | 壁纸与颜色 / 回答完成提醒 / 先计划后执行 | 原「外观」+「通知」+「任务执行」 |
| 设备能力 | 自动化总开关 / 权限中心 / 后台存活自检 | 原「设备能力」（调试通道搬走） |
| 工具 | 模型配置、容器、编辑器、提示词库、收藏、MCP、创作工坊、构建 | 不变 |
| 数据 | 技能中心 / 运行日志 / 记忆库 / 导出备份 / 恢复备份 | 原「数据」+「备份与恢复」 |
| 帮助 | 重看上手引导 / 关于与帮助 | 原「帮助」+「关于」 |

判断依据是「两行是不是在回答同一个问题」：

- 外观、通知、执行方式 → 都是「这个 App 怎么表现」
- 技能、日志、记忆、备份 → 都是「这台手机上存了什么、怎么带走」
- 上手引导、关于 → 都是「不会用 / 想了解时去哪」

## 顺带一处措辞修正

「先计划后执行」原来把状态写进标题（`先计划后执行（PLAN）` / `自动执行（AUTO）`），
开关一拨标题就变，读起来像在切换模式而不是开关。现在标题固定，状态进副标题
（「已开启：3 步以上任务先弹计划卡片」），和「自动化总开关」的写法一致。

## 自查

- 设置页卡片数：10 → 6（不含顶部 hero 卡）。
- 调试通道在设置页的引用已全部清除（只剩注释里提到）。
- `AdbChannelSection` 与 `SettingsScreen` 共用 `AkGroup` / `AkListItem`，观感一致。
- QA `R8` 原来断言 `title = "备份与恢复"`，分组名变化后改为断言「导出备份」仍在设置页，
  不锁组标题（分组属于信息架构，会随需求调整）。

与存储逻辑；回滚只需还原 `SettingsScreen.kt` 并删除新文件。
