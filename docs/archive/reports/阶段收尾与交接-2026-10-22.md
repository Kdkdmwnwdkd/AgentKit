### 1.4 加场 · QA 硬门禁

**问题**：`run-all.sh` 把 `known-broken.txt` 里的 harness 归为 XFAIL，**不阻塞构建**。
副作用是——新引入的失效 harness **只要往清单里加一行**，就能长期挂在 CI 上不被人发现。
上面那 3 条能长期挂着，正是因为这个。

**修法**：新增 `scripts/qa/gate.sh`，只卡三件**确定的事**：

| 检查 | 判据 |
|---|---|
| ① 清单归零 | `known-broken.txt` 非注释条目数必须为 0（文件缺失也算失败，不能默默放行） |
| ② 汇总无失败 | QA 汇总行 `FAIL=` 必须为 0 |
| ③ 无 XPASS | 日志里不得出现 `XPASS`（XPASS = 有人修了但没同步清单） |

刻意**不**卡「某 harness 因环境不具备而 SKIP」——QA harness 保持 `continue-on-error: true`
（report only），门禁只做确定性判断，不会误伤。

- 门禁自身也有自测：`scripts/qa/run-gate-verification.sh`，**7 场景 / 14 断言**，全绿。
- `run-all.sh` 自动收录 `run-*.sh`，所以**门禁失效会被门禁自己发现**。
- 逃生阀：仓库变量 `QA_GATE=warn` 只告警；`QA_HARNESS=off` 整步跳过。

### 1.5 C 批 · 三个方向（每个都修掉了一个真实产品缺陷）

#### C1 · 备份按文件分组 + 批量回滚

- `FileBackupStore` 新增 `FileGroup` / `grouped()` / `restoreFile()` / `restoreAll()`。
- `EditorScreen` 从平铺列表改为**按文件分组**卡片，顶部「共 N 个文件、M 次改动」+「全部回滚」。
- **倒序恢复是硬不变量**：设原内容 C0，Agent 依次写 C1/C2/C3，对应备份
  b1(before=C0)/b2(before=C1)/b3(before=C2)。正序恢复（b1→b2→b3）最终停在 C2，**退不干净**；
  必须倒序（b3→b2→b1）才回到 C0。

#### C2 · 从中断处续跑

- `AgentRunStateStore` 新增 `advance(toolName)` / `buildResumeContext()` / `markResumed()`。
- `ChatViewModel` 接入：`ToolFinished` 事件推进步数；识别「继续」类短指令；
  拼入上次进度摘要；续跑时保留上次 `prompt`/`stepIndex`/`startedAt`/`doneTools`。
- `isResumeIntent()` 只认 **≤12 字**的短指令（继续 / 接着 / 接着做 / continue / resume…），
  否则「继续帮我写个函数」会被误判成续跑，把上一轮无关上下文硬塞进来。

#### C3 · 指定版本的运行时

- `ToolchainInstaller` 新增 `VersionSpec` / `resolveVersion()`；`installCommand` 支持版本约束。
- `ContainerToolchainTool` 暴露 `version` 参数；`ContainerScreen` 补 UI 入口（逐语言版本输入框）。
- 版本号严格白名单 `^[0-9]+(\.[0-9]+)*$`（**会拼进 shell 命令**，必须防注入）。
- **非法版本明确报 `bad_version`，不静默当默认版**——用户要 node 18 却悄悄装了 node 20，
  比直接报错更糟。

### 1.6 顺手修掉的 5 个真实缺陷

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| ① | 备份 id = `时间戳+路径`，**同毫秒内对同一文件的连续写入算出相同 id** | **静默丢备份**——「改了三次只剩一条」，界面看不出异常，批量回滚退不干净 | id 加全局单调 `seq`（companion object 级；时钟回拨也不复用序号） |
| ② | `list()` 只按 `timeMs` 排序，而 `sortedBy` 是**稳定**排序 + `listFiles()` 顺序随机 | 同毫秒备份的先后**随机**，倒序恢复顺序随机 → 退不干净 | `seq` 落进 `.meta` 并回读，排序改 `(timeMs, seq)` 复合排序 |
| ③ | `stepIndex` / `doneTools` **只在初始化被赋值**，之后再没动过 | 中断提示永远「第 0 步」、完成过的工具永远为空，**恢复信息形同虚设** | 新增 `advance()`，在 `ToolFinished` 事件里推进 |
| ④ | CI 里 `bash run-all.sh \| tee log` 后取 `$?` | `$?` 是 **tee 的退出码**（恒为 0）→ **失败被伪装成成功** | 改用 `${PIPESTATUS[0]}` |
| ⑤ | Release 步骤 `gh release create \|\| gh release upload --clobber` | tag 已存在时 create 失败，upload **不改 title** → release 标题永远停在首次创建的 run 号（实测停在 "run 321"，包却是 run 334 的） | 三步：create (`\|\| true`) → upload --clobber → **edit** 刷标题/说明 |

### 3.3 环境限制导致的未闭环

- **本地出不了 APK**：仓库的 native 依赖 `llama.cpp`（`scripts/fetch-llama.sh` 拉取，不进 git），
  沙箱离线拉不到 → `assembleDebug` 在 native 阶段失败。**所以编译出包只能靠 CI**。
  本地能做的只有 `compileDebugKotlin`（Kotlin 层）。
- **Gradle wrapper 在沙箱会卡住**：`gradlew` 要下载 gradle 发行包，网络慢（实测挂 54 分钟）。
  用 `/opt/gradle-8.9/bin/gradle` 直接跑，19 秒出结果。

### 3.4 网络与沙箱（**这一节请务必先读**）

沙箱访问 GitHub 的通道有讲究，走错通道会白花几十分钟。
本轮实测：下载 34 MB 的 APK artifact，API 直连花了 **40 分钟**，
改用 `gh-proxy.com` 直链只要 **4 分钟**（快 10 倍）。

详细通道说明、可用 API、以及三个反复踩的坑（"Bad credentials" 大概率不是令牌失效、
gh-proxy 不能带 auth、WebFetch 有 15 分钟缓存）见：

> **`docs/沙箱网络与GitHub通道说明.md`**

### 3.5 其它已知边界

- **推送方式受限**：沙箱里 git 协议直连 github.com:443 会超时，**只能用 GitHub REST API 造 commit**。
  由此产生两个必须记住的坑：
  1. **本地 git 历史与远端历史是两套**，`git rebase` 不可靠。正确姿势是
     「以远端 head 为 parent + 显式文件列表」造 commit。
  2. 远端 head 的 commit 在本地 git 里**不存在**，`git rev-parse <sha>^{tree}` 会直接失败——
     base_tree 要从 API 取。
  3. **不要用 compare API 的文件列表重建 tree**——它**会漏文件**（上一轮 `known-broken.txt` 就被漏掉，
     合并后没进远端）。合并时直接用**分支 head 的 tree**。
- **artifact 下载极慢**（34 MB 要 40 分钟，必须 `curl -C -` 断点续传）。
- **Release asset 直链下载会被 CDN 卡住**（实测卡在 3.6 MB 不动），走 artifact 更稳。

### 3.6 第四轮实测补充（2026-10-23 下午）

详细见 **`docs/模拟器实测-第四轮-2026-10-23.md`**。这里只列结论：

**新修 1 个 P0**：空回复「沉默失败」——模型返回 200 但内容为空时，界面上什么都不出现，
用户分不清是没发出去还是模型抽风。已补提示气泡（上屏 + 落库 + 日志），11 条断言，真机验证。

**补完上一轮没验的**：P1-7 停止生成保留内容 —— 落盘确认 `variant[0]` 是 49 片已生成内容，
`variant[1]` 是独立停止提示。

**方法学（最重要，务必记住）**：`adb install -r` **覆盖安装后 App 仍执行旧代码**，
即使 APK 里的 dex 已是新代码（可反编译验证、设备 APK md5 也一致）。
**改代码后验证必须 `adb uninstall` + `install`**，否则会把「没生效」误判成「代码写错了」。

**确认做不到的**：B4 容器内 `node --version` —— `assets/containers/alpine.tar` 里的
`busybox` 是 **ARM aarch64**（`file` 已确认），x86_64 模拟器上 proot 起不来。

**新发现未修（P3）**：抽屉「最近对话」在 720×1280 上首屏一条都看不见

## 五、给下一个人 / 下一个会话的四条硬提醒

0. **先读 `docs/沙箱网络与GitHub通道说明.md`**——选错通道会在下载上白花几十分钟
   （APK 走 `gh-proxy.com` 直链，4 分钟 vs 40 分钟）。开工前先跑一次 DNS 检查确认
   当前是通还是被拦。

1. **别在本地找 APK**——`llama.cpp` 拉不到，native 编不出来。**编译出包靠 CI**。
   本地只跑 `compileDebugKotlin` + `scripts/qa/run-*.sh`。

2. **推代码用 API，不用 git**——沙箱 git 协议连不上 github。
   用 `push_commit_via_api.py`（文件清单显式传）+ `merge_via_api2.py`（直接用分支 head 的 tree）。

3. **QA 门禁现在是硬的**——`known-broken.txt` 非空、汇总 `FAIL>0`、出现 XPASS，
   **任何一条都会让 CI 红**。如果看到 CI 因为这三件事红了，那不是误伤，是真有问题：
   要么修代码，要么修清单（并且顺手确认一下是不是该把清单删干净——它现在应该是空的）。
