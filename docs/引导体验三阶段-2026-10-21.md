## 二、P0 权限引导页

### 新增文件

- `core/capability/PermissionGuide.kt` —— **纯函数**模型（零 Android 依赖）
- `ui/PermissionGuideScreen.kt` —— 引导页

### 五项能力与分级口径

| 项 | 是否硬门槛 | 判定来源 |
|---|---|---|
| 无障碍服务 | **是**（唯一） | `AutomationBridge.service != null` |
| 通知访问 | 否 | `enabled_notification_listeners` 含本服务 |
| 使用情况访问 | 否 | AppOps `OPSTR_GET_USAGE_STATS` |
| 电池优化白名单 | 否 | `PowerManager.isIgnoringBatteryOptimizations` |
| 调试通道（Shizuku） | 否 | `ShizukuShell.UiState` 四态 |

**为什么只有无障碍是硬门槛**：`CapabilityChain` 里 `control_screen` 只有无障碍一条路径，缺了就是全链不可用；其余缺失只降低能力上限。所以引导页用「必需 / 可选」两个徽章区分，缺失的可选项**不构成阻塞**，也不会出现在抽屉红点里（`pendingGrantCount` 仍只算三项，harness 有断言守着）。

### 交互

- 顶部：`已就绪 N/5` + 4dp 进度条 + 一句「现在能做什么」（`capabilitySummary` 给结论，不重复列表内容）
- 每项：标题 + 状态徽章 + 「开启后能做」+（未开启时）「现在：缺什么」+ 动作按钮
- 动作文案按缺什么给什么：`去开启` / `去设置` / `一键安装` / `打开 Shizuku` / `去授权`
- 从系统设置返回触发 `ON_RESUME` → `refreshGrants()`，不需要手动刷新
- 底部主按钮：无阻塞时「开始使用」，有阻塞时「先这样，去对话」+ 一行说明
- 跳过/完成都落 `agentkit_permission_guide.guide_seen`，不再自动进入，但入口常驻

### 接入点

- 权限中心页顶部新增「权限引导」卡（常驻，不因全部已授权而隐藏——换机/重装后还要走）
- 首启 `OnboardingDialog` 末尾的灰字改成一条可点岔路：「想让它替你操作屏幕？[去开启]」
- 模型配置完成后首次进对话页，若权限引导没走过 → 自动进入一次（走正常压栈，可按返回）

## 三、P1 配模型路径

### 3.1 Key 获取直达

- `ProviderCatalog.CONSOLE_URLS` + `consoleUrlOf(id)`：覆盖全部需要 Key 的 30 家供应商
- 本地部署（Ollama / LM Studio / vLLM / 内置）与未收录 id 返回空串 → UI **不渲染**（宁可不显示，也不给错链接）
- 模型页在 `apiKey.isBlank()` 时显示「去 <供应商名> 获取 API Key」，点击系统浏览器直达控制台
- harness 断言：需要 Key 的非本地供应商一个都不能缺、地址必须 https、本地与自定义 id 必须为空

### 3.2 失败归因（新增 `core/llm/ConnectionDiagnosis.kt`，纯函数）

| 信号 | 归因 | 给用户的动作 |
|---|---|---|
| 401 / 403 | Key 无效或无权限 | 去获取 / 更换 Key |
| 402 | 余额不足 | 去获取 / 更换 Key |
| 429 | 限流 | 重试（文案明确「不是 Key 错了」） |
| 404 | 端点或模型不存在 | 选择可用模型 |
| 400 且响应体含 `model` | 模型名不被接受 | 选择可用模型 |
| 400 其它 | 端点/参数问题 | 无按钮，指路改 Base URL |
| 5xx | 服务端 | 重试（文案说明不是用户的配置问题） |
| `UnknownHostException` | 域名解析失败 | 指路改 Base URL |
| `SocketTimeoutException` | 网络不通 | 重试（提示局域网用 http:// 带端口） |
| `SSLException` | TLS 握手失败 | 指路检查 http/https |
| `ConnectException` | 端口没有服务 | 重试（提示查端口） |

结果卡 `TestResultCard` 据此渲染**一个**按钮；`TestResult` 增加 `kind` / `action` 两个字段承载结论。

### 3.3 成功即收尾

测试通过后结果卡出现「保存并回到对话」：改过配置就保存（`onSave` 内含 `updateConfig` + 返回），没改过直接返回。用户不必自己找返回键。

## 四、P2 聚光灯引导

### 实现

- `ui/SpotlightGuide.kt`：`GuideAnchor` 枚举 + `GuideAnchorRegistry`（`mutableStateMapOf<GuideAnchor, Rect>`）+ `Modifier.guideAnchor()` + `SpotlightGuide` 覆盖层
- 锚点由组件**自己上报** `boundsInRoot()`，不硬编码坐标（机型、字号、键盘弹起都会变）
- 遮罩用 `Path` + `PathFillType.EvenOdd`：外框减内洞，目标区域保持原亮度，再描 2dp primary 边
- 卡片自动放在洞的另一侧（洞在上半屏则卡片贴底），点任意处 / 「下一步」推进，「跳过」结束

### 三个锚点

`输入栏 → 发送键 → 顶栏汉堡（抽屉）`

**为什么不是原计划的五个**：权限红点与技能市场在抽屉里。抽屉关闭时内容仍在组合树中，但被 `offset` 推到屏幕外，遮罩会在屏幕外开洞——真机上就是「一片黑，什么都没高亮」。要做对必须在引导中自动展开抽屉并等动画结束，把一个纯展示层变成状态机。收益不抵风险，因此收敛为三个常驻锚点，抽屉里的内容写进第三步正文。

### 触发与重看

- 触发三连：模型已就绪 + 权限引导已走过 + 自己没被跳过（`spotlight_seen`）
- 设置页新增「引导」组：「重看上手引导」（清标记并回对话）、「权限引导」（直达页面）
- 跳过 ≠ 永远错过：入口常驻设置页

### 未覆盖的风险（如实记录）

1. 真机未验证：引导页五项的跳转 intent 在部分 ROM 上可能落到「应用详情」而非目标页（已按现有权限中心的老路复用，风险与旧版一致）。
2. 聚光灯在宽屏（≥840dp）下没有汉堡按钮，第三步会被自动跳过（已有 `rect == null` 兜底，逻辑上安全，但视觉上会少一步）。
3. Shizuku 三态文案沿用旧口径，未做真机回归。
