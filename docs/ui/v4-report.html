依据：我用了哪些规则，拒了哪些

参考 Leonxlnx/taste-skill（MIT 许可，约 96k star）的 references/app-screens.md。它有落地页和工具型 App 两套规则，而且明确写着落地页那套不适用于 App 界面——所以我只取了工具界面的条款。

采纳 · app-screens 禁忌"Icons in boxes repeated down a list" —— 列表里每行都套图标盒
已落地。20dp 线性图标直接贴行首。这是这一批最核心的一条。
采纳 · 密度分级medium 密度 44–56dp，sparse 56–92dp
已落地（部分）。双行 72→64，落在 sparse 下沿；单行维持 56。没压到 56 以下，因为双行塞不进。
采纳 · 标题尺度App 顶栏标题 20–24px 才构成层级
已落地。18→20sp。同时保持单行省略，不改导航结构。
拒绝 · 落地页语汇hero 大标题、240px 留白、图片主导、超大字号
不采纳。那是营销页的做法。工具型 App 的密度要求相反——用户要的是"一屏看到更多"，不是"一屏只放一句话"。
拒绝 · 推翻现有配换掉暖纸底色 / 主色 / 圆角体系
不采纳。现有 v3 的暖纸 DNA（#F8EFE9 / #0E5D6B）是连贯的，推倒重来只会换来一次无收益的返工。这次只调"排布"，不动"调色板"。
