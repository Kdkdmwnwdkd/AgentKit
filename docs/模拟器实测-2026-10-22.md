# 安卓模拟器实测记录（2026-10-22）

> 目的：不再只靠读代码判断 UI。在 InstaBox 的 4C/8G/20GB 云机器上装无头 Android 模拟器，
> 把 APK 装进去、逐页点、逐页截图、抓崩溃，查出真机才会暴露的问题。
>
> 结论：**跑通了，但只能软件模拟（无 KVM）**；查出并修掉 **4 个真缺陷**，全部在模拟器上复验通过。

---

## 一、这台机器能不能跑模拟器

| 检测项 | 结果 | 含义 |
|---|---|---|
| `ls /dev/kvm` | 不存在 | 没有硬件加速 |
| `grep -o svm /proc/cpuinfo` | 有 `svm`（AMD-V） | CPU 层面透传了虚拟化标志 |
| `/lib/modules/$(uname -r)` | 不存在 | 内核是定制的，**没有可加载模块**，`modprobe kvm` 不可用（连 `modprobe` 命令都没有） |
| `mknod /dev/kvm c 10 232` + open | `ENODEV` | 内核没注册 kvm 驱动，造设备节点也没用 |
| `lscpu` | `Hypervisor vendor: KVM`（L1） | 这是「我们本身就跑在 KVM 上」，不代表能再套一层 |
| kernel | `6.18.54-instabox`，Debian 13 | — |

**结论：嵌套虚拟化不可用，Android 模拟器只能走 QEMU TCG 软件模拟。**
`svm` 标志存在只说明宿主没屏蔽 CPUID，但 guest 内核没有 kvm 驱动，等于没用。

## 二、跑起来用了什么

| 项 | 取值 | 为什么 |
|---|---|---|
| 镜像 | `system-images;android-30;default;x86_64`（AOSP） | **不要用 `aosp_atd`**：ATD 是自动化测试专用镜像，**没有 SystemUI/Launcher，整屏是黑的**，什么都看不到（踩过） |
| 分辨率 | 720×1280 @320dpi | 1080×2340 在 TCG 下负载 12，system_server 直接被压死（DeadSystemException） |
| 内存 / 核 | 3072MB / 3 vCPU | 2C+2GB 也会把 system_server 拖死 |
| 图形 | `-gpu swiftshader_indirect` | 无 GPU；宿主侧 SwiftShader |
| 其他 | `-no-window -no-audio -no-boot-anim -no-snapshot -accel off` | 无头 |
| 系统设置 | `hide_error_dialogs=1`、三个动画 scale=0 | 否则 SystemUI 的 ANR 弹窗会盖住界面，截的全是弹窗 |
| 开机耗时 | **约 4–5 分钟**（TCG） | 可接受；之后单次操作 3–10 秒 |
| SDK 占用 | 7.4GB（含两套镜像） | 20GB 盘够用，但要清理旧镜像 |

### APK 怎么装进去

官方 debug 包只带 `arm64-v8a` 原生库，x86_64 模拟器会 `INSTALL_FAILED_NO_MATCHING_ABIS`。
两条路，都验证过：

1. **剥库重签**（不用改代码）：删掉 `lib/` → `zipalign` → `apksigner` 用临时 key 重签。
   两个 JNI 入口（`LlamaJni` / `TerminalJni`）都是**懒加载 + try/catch 降级**，缺 `.so` 只影响本地推理和内置终端，界面照常。
2. **`-PnoNative=true` 构建**：`app/build.gradle.kts` 里跳过 CMake 与 `abiFilters`，
   并（2026-10-31 补）在 `packaging.jniLibs.excludes` 里排掉 `**/*.so`——
   否则 `src/main/jniLibs` 下预置的 proot/busybox 等 arm64 库照样进包，仍会 ABI 不匹配。
   现在直接 `assembleDebug -PnoNative=true` 就能装，**不用再手工剥库重签**（第 1 条仅在
   手上只有官方包、又不能改构建时用）。CI 与正式包不受影响：那是 `skipNative=false` 分支。

## 三、查出来的 4 个真缺陷（都已修 + 复验）

| # | 现象（模拟器截图） | 根因 | 修法 |
|---|---|---|---|
| 1 | 720×1280 上首启弹窗**超出屏幕**，「先自己看看」被裁掉一半、看不到 | 弹窗内容 Column 无高度上限、不可滚动 | 内容区 `heightIn(max=520.dp)` + 上半区 `verticalScroll`，两个按钮固定卡片底部 |
| 2 | 模型页只剩「模型」一个 Tab，**本地模型 / 提示词 完全不可见** | Tab 列里用 `Box(fillMaxWidth)` 当下划线：Row 把剩余宽度全给了第一个 Tab，后两个被挤出屏幕 | 下划线改成 `Text.drawWithContent` 按文字自身宽度画，不再吃宽度 |
| 3 | 在模型页保存后回到对话页，**没有自动进权限引导** | 自动引导的 `LaunchedEffect` 只以 config 为 key；配置变化那一帧还停在 MODEL 页，effect 提前 return，回 CHAT 后不再重跑 | key 加上 `route` |
| 4 | 权限引导页底部「开始使用 / 先这样，去对话」**看得见、点不动** | 页面内容没有避让系统导航栏，按钮落在导航栏区域，触摸被系统吞掉 | 四个长页面（引导 / 权限中心 / 设置 / 模型）滚动容器加 `navigationBarsPadding()` |

### 复验证据（截图）

- 缺陷 1：修前 `f2.png`（按钮被裁）→ 修后 `f3.png`（两个按钮都在）
- 缺陷 2：修前 `m1.png`（只有一个 Tab）→ 修后 `t1.png`（模型 / 本地模型 / 提示词 三个）
- 缺陷 3：修后 `t8.png`（保存后直接落在权限引导页）
- 缺陷 4：修后 `n2.png`（CTA 上移到导航栏之上）→ 点一下 `n3.png`（成功跳回对话并弹出聚光灯）

## 四、跑通了什么（除了找 bug）

| 流程 | 结果 |
|---|---|
| 首启「三步开始」弹窗 | 正常；小屏可滚动、按钮可点 |
| 权限引导五项检测 | 无障碍 / 通知 / 使用情况 / 电池白名单 四项**逐个用 adb 打开后计数从 0/5 → 1/5 → 4/5**，进度条与文案同步（「只能对话」→「能替你操作手机」→「只能感知」） |
| 回到页面自动复检 | 从系统设置返回触发 `ON_RESUME`，数字自己变（不需要点刷新）；用 `am start` 强制 relaunch **不会**触发（本来就不该） |
| 聚光灯三步 | 洞精确框住输入栏 → 发送键 → 汉堡按钮，遮罩与描边正常，`开始使用` 可结束 |
| 设置页「引导」组 | 「重看上手引导」「权限引导」两个入口都在，描述正常截断 |
| 模型页 Key 直达 | 空 Key 时显示「去 OpenAI 官方 获取 API Key ↗」（通用 id 显示为 OpenAI 官方，不是「OpenAI 兼容」） |
| 崩溃 | 全程 `logcat -b crash` 为空；只有 WebView Crashpad 建目录失败等无害日志 |

## 五、这轮**没能**验证的（别当成已验收）

1. **Shizuku 三态**：模拟器没装 Shizuku，只看到「未安装 / 一键安装」这一态。
2. **真实模型对话**：只填了假 Key，验证的是 UI 与流程；没有真正发请求。
3. **无障碍实际执行**（点击/滑动/读界面）：只验证了「服务被系统连上、计数变化」，没让 Agent 真去操作。
4. **本地推理 / 内置终端**：测试包没有 `.so`，这两块按设计是降级不可用。
5. **多分辨率**：只测了 720×1280@320 与 1080×2340@440（后者太慢，未跑完整流程）。
6. **Android 版本**：只测 API 30；API 33/34 的行为差异（通知权限、前台服务类型）未覆盖。

## 六、复现步骤（下次直接用）

```bash
# 1) 装 SDK（约 4GB）
SDK=$HOME/android-sdk
mkdir -p $SDK/cmdline-tools && cd /tmp
curl -fsSL -o cmdtools.zip https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip
unzip -q cmdtools.zip -d $SDK/cmdline-tools && mv $SDK/cmdline-tools/cmdline-tools $SDK/cmdline-tools/latest
yes | $SDK/cmdline-tools/latest/bin/sdkmanager --sdk_root=$SDK --licenses
$SDK/cmdline-tools/latest/bin/sdkmanager --sdk_root=$SDK \
  "platform-tools" "emulator" "system-images;android-30;default;x86_64"

# 2) 建 AVD（720p / 3GB / 3 核）
echo no | $SDK/cmdline-tools/latest/bin/avdmanager create avd -n ui30 \
  -k "system-images;android-30;default;x86_64" -d pixel_5 --force
C=$HOME/.android/avd/ui30.avd/config.ini
sed -i 's/^hw.ramSize *=.*/hw.ramSize = 3072/' $C
sed -i 's/^hw.cpu.ncore *=.*/hw.cpu.ncore = 3/'   $C
sed -i 's/^hw.lcd.width *=.*/hw.lcd.width = 720/'  $C
sed -i 's/^hw.lcd.height *=.*/hw.lcd.height = 1280/' $C
sed -i 's/^hw.lcd.density *=.*/hw.lcd.density = 320/' $C

# 3) 启动（TCG，约 4-5 分钟）
$SDK/emulator/emulator -avd ui30 -no-window -no-audio -no-boot-anim -no-snapshot \
  -accel off -gpu swiftshader_indirect -memory 3072 -cores 3 &

adb wait-for-device
until [ "$(adb shell getprop sys.boot_completed 2>/dev/null | tr -d '\r')" = "1" ]; do sleep 10; done

# 4) 关掉动画与错误弹窗（否则 SystemUI ANR 会盖住界面）
adb shell settings put global window_animation_scale 0
adb shell settings put global transition_animation_scale 0
adb shell settings put global animator_duration_scale 0
adb shell settings put global hide_error_dialogs 1

# 5) 出无 native 的测试包并安装
./gradlew :app:assembleDebug -PnoNative=true
adb install -r -t app/build/outputs/apk/debug/app-debug.apk

# 6) 截图（宿主侧截图更可靠：adb exec-out screencap 在 ATD 镜像上全黑）
adb exec-out screencap -p > shot.png
```

## 七、给下一次的提醒

- **先测 `/dev/kvm` 再决定方案**：有 KVM 一切好办；没有就只能 TCG，别在 1080p 上硬跑（会把 system_server 压死）。
- **别用 ATD 镜像做肉眼验收**：它没有 SystemUI，黑屏不是 App 的问题。
- **模拟器里的点击要用「物理像素」坐标**，截图被我这边工具缩放过（607×1080 vs 720×1280），换算错一次就会点空。
- **TCG 下 `uiautomator dump` 可能滞后**：dump 里看不到的控件，截图里可能已经在了；两者冲突时以「重新截图 + 长等待」为准。
- **每轮改完都要重新出包装机**：`-PnoNative=true` 出包 40 秒，装上 30 秒，比推 CI 等 15 分钟快得多。
