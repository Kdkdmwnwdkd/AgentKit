## 一、为什么要搞这个

七块功能各自回应一个真实痛点（编号沿用功能清单 W3–W9）：

- **W3 审批档位**：审批弹窗要么太吵（事事都问）要么太险（啥都不问）。做成 STRICT / STANDARD / AUTO 三档，坏配置自动回 STANDARD，AUTO 按「界面操作免审、写文件 / 推仓库必审」的规则免打扰放行日常操作。
- **W4 提示词变量**：技能提示词里写 `{{变量}}` 就能提取成填槽表单，缺值不做半填，防止拼出半残提示词。
- **W5 SSH 远端 shell**：复用现有 ssh 命令行语义，远端执行不进自动降级链（连不上就明说，不悄悄降级），档案不落密码字段。
- **W6 本地知识库检索**：知识库建好得能用——BM25 纯函数检索 + `knowledge_search` 工具，全程本地。
- **W7 费用下钻**：模型调用按模型记归属，设置页出「费用参考」分区，花在哪一眼看清。
- **W8 二维码配置导入导出**：换机迁移配置。零第三方依赖自写 QR 编码器（版本 1–13，纠错 L/M），**负载层 Key 绝不进码**。
- **W9 长对话全档保留**：超限对话轮转归档成 JSONL，导出时归档轮接上、轮号连续，历史不再丢。

## 二、怎么搞的

每块独立提交、独立可回退，全程零第三方新增依赖。几个值得一提的设计决定：

- 检索（W6）和二维码（W8）都走纯函数层：判定逻辑不碰 UI、不碰网络，行为断言可以真编真跑。
- 二维码编码器从零写：版本信息 BCH 校验位在调试期抓出错位真 bug（对拍回读抓出）。
- 长对话导出改带第二参（归档轮），轮号带总数「第 N/总数 轮」，检查器断言随之同步并注明缘由（盯语义不盯字面）。
- 费用分组放模型页签，不放提示词页签（避免语义错位）。
