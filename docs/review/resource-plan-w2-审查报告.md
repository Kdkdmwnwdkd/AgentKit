## 一、为什么要搞这个

低配手机跑本地模型，线程数、上下文长度、GPU 通路都得量机而行，不能一套参数打天下。目标：

1. 按机型画像自动分三档：**省电（4 线程 / 4K）/ 均衡（6 线程 / 8K）/ 性能（8 线程 / 16K）**；
2. 自动档**只减不增**：用户手动调低的设置永远不被程序抬高；
3. 锁档优先：用户明确选了档位，就照办，机器画像只供自动档参考。

另外还有个被动原因：启动早期机型画像还没探测出来，代码里两处直接把「可能为空」的画像塞给了分档规则，编译器直接报错（run 483 同款），不改不行。

## 二、怎么搞的

- **分档规则纯函数层**（ResourcePlan.kt）：AUTO 档按画像映射三档；用户锁档解析失败回自动；**画像缺失时不猜档**——参数原样生效、不压线程、不封上下文、不瞎建议安全模式，锁档照常。
- **两处崩溃修复**：34c9523 修第一处（缺失画像不套档位），01ae30f 修第二处（LocalLlamaClient 画像可空调用点）。
- **设置页**：档位单选 + 视图模型状态与 setter，客户端读档位走统一入口。
