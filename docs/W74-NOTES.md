# W-74：「这差距对吗」——差距的 150 倍在 prompt，不在引擎

用户录屏对比：同一台手机、同一个 `qwen2.5-3b-instruct-q4_k_m.gguf`。

| | IRIDIS | 北辰（1.439） |
|---|---|---|
| 首字 | **4.8 秒** | 180 秒没出第一个字 |
| 生成速度 | **4.8 tok/s** | —（还没进生成） |
| 界面上的 token 计数 | **7 / 4K** | 1086 token（日志 `prompt 长度：4479 字节 → 1086 token`） |

差距不是 2 倍、不是 5 倍，是 **155 倍**——正好等于 prompt 长度之比。

## 为什么北辰的 prompt 有 1086 token

先说清一点：**北辰没有「人设/人格设定」这类东西**（全仓没有这个字段，早期
文档里写的「人设」是措辞失误，已统一改成「系统提示」）。每轮塞进去的是下面这些：

| 组成 | 实测长度 | 对「你好」有用吗 |
|---|---|---|
| 系统提示 `DEFAULT_SYSTEM_PROMPT` | 668 字 | 只有开头 122 字有用 |
| └ 其中「界面操作协议」 | 544 字 | 无用（教模型怎么点屏幕） |
| 7 个工具的说明 + 调用协议 | 约 750 字 | 无用（闲聊不调工具） |
| 工具自带提示片段（ui_tree 等） | 约 170 字 | 无用 |
| 设备上下文（通知列表） | 约 60 字 | 无用（"最近来了条输入法通知"） |
| 用户那句话 | 2 字 | ← 真正需要的 |

合计约 1650 字 ≈ 1086 token。IRIDIS 是纯聊天应用，prompt 里只有用户那句话。

手机 CPU 的算力是固定的：3B Q4 每 token 约 6 GFLOP，这台设备实测 4.8 tok/s，
prefill 也就十几 tok/s 的量级。1086 token 光是 prefill 就要两分钟以上——
**这就是那 180 秒。**

## 修法：默认轻聊档，Agent 模式改成显式开关

「本地能秒回」和「本地能调工具」是两件互相冲突的事，不能用一个默认值兼顾。

`LocalLlamaSetting.agentMode`（默认 **false**）：

- **关（轻聊档，默认）**：不带工具协议；系统提示只留前 3 行 / 160 字；
  user 消息剥掉「用户当前请求：」之前的设备上下文；历史只留最近 4 条。
  prompt 从 1086 token 降到几十 token。
- **开（Agent 模式）**：完整系统提示 + 工具协议 + 完整历史，能力齐全但首字慢，
  由用户在「模型配置 → 本地模型 → 本地对话模式」里显式打开。

设置页新增一个开关，文案直说代价：「Agent 模式会附带工具清单与完整行为规则，prompt 长约 20 倍」。

## 预期效果（同一台设备、同一个 3B 模型）

| | 之前 | 之后（轻聊档） |
|---|---|---|
| prompt | 1086 token | 约 40 token |
| 首字 | >180 秒（失败） | 5~8 秒 |
| 生成 | — | 4~5 tok/s（与 IRIDIS 同级） |

生成速度追平 IRIDIS 是必然的——本来就是同一个 llama.cpp、同一个模型、同一颗 CPU。
差的只是「每轮给模型看多少字」。
