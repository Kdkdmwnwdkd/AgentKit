## 二、踩过的坑（重点资产：现象 → 根因 → 修法 → 防复发）

### A. 构建与工程纪律

| # | 现象 | 根因 | 修法与防复发 |
|---|---|---|---|
| A1 | 本地编译过、CI 干净构建失败（run 38754108526） | 改了接口默认参数（`send/run` 加 images），漏改同契约的另一个实现类（适配层 `core/AgentLoop`）；**增量构建未完整校验** | **接口签名变更必须干净构建**（`--rerun-tasks`）后再推送；此后每轮都跑干净构建 |
| A2 | `fatal: not a git repository`（反复踩） | 沙箱 shell 工作目录每轮重置为 `/workspace`（非仓库根） | 所有命令带 `cd /workspace/AgentKit &&` 前缀或绝对路径 |
| A3 | `gradlew` EXIT=126/127 | 无可执行位 / 路径不存在 | 一律 `bash /workspace/AgentKit/gradlew -p /workspace/AgentKit` |
| A4 | commit message 的正文被吃掉 | zsh 把反引号当命令替换执行 | **提交一律用消息文件** `git commit -F /tmp/msg.txt` |
| A5 | harness 自建编译报缺 coroutines / JB_ANNOTATIONS | 手工 javac 式编译缺完整类路径 | **必须用官方 runner** `bash scripts/qa/run-*.sh`（内含 kotlin-compiler-embeddable + stdlib + coroutines + annotations + `-Xfriend-paths`） |
| A6 | harness 编译错「unresolved reference」但源码没问题 | 断言字符串里的 `${...}` 被 **harness 自身 Kotlin** 解释 | 写断言时转义 `\${...}` |
| A7 | 新 harness 断言与旧产品变更冲突（陈旧断言批量失败） | 断言锚定了旧实现文本 | 产品变更时**同步更新断言**并在注释写明「随产品变更更新」，避免误判为回归 |
| A8 | 下载 CI 产物三次失败（540s 超时 / exit 9） | api.github.com 直连 ~35KB/s；沙箱后台任务 **10 分钟上限**（SIGKILL） | `curl -C -` 断点续传分批下；**gh-proxy.com 镜像实测 4.7MB/s** |
| A9 | 推送间歇失败（TLS -110 / 443 超时） | 网络对 github.com 不稳定 | 推送用**重试循环并真实捕获退出码**；`gh` 需显式 `-R` 仓库 + `GH_TOKEN` 从 remote URL 提取 |

### C. 供应商协议兼容（本项目的核心复杂度来源）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| C1 | **DeepSeek 聊天随机崩**：「Element class kotlinx.serialization.json.JsonNull … is not a JsonObject」 | kotlinx 的 `.jsonObject/.jsonPrimitive/.jsonArray` 是**硬转换**（`as` 强转），遇到 JSON 显式 `null` 即抛；DeepSeek 会真实下发 `"delta": null`（收尾块）、`"reasoning_content": null`（非推理回合）、`content: null`。**hotfix26 引入 reasoning 解析后开始踩**（此前不读该字段不崩） | 新增 `core/llm/JsonSafe.kt` 三个 `as?` 软转换（`objOrNull/arrOrNull/primOrNull`），LLM 链路 **7 文件 93 处**全替换 + 去 `!!`/`.first()`；缺字段退化为「没有」而非崩溃（hotfix33） |
| C2 | **「测试连接正常、聊天却崩」** | 两条不同代码路径：测试连接走**整段响应**解析、聊天走**流式分片**解析；后者才容易出现 null 片段 | 两条路径都做安全化；诊断时**先分清走的是哪条路径** |
| C3 | 「不一个字一个字显示 / 有时直接整段 / 有时空白」 | 部分端点/中转**忽略 `stream: true`**，直接返回整段 JSON。旧实现逐行找 `data:` 前缀，一条都没匹配 → 最终产出**空回答** | `SseReadOutcome` 判定：整段无 `data:` 行 → 走 `parseResponse` 非流式解析降级为一次性输出；三家通道（OpenAI 兼容 / Claude / Gemini）**对称**处理；并 `AgentLogger` 留痕（hotfix35/36） |
| C4 | 思考过程（思维链）三家字段各异 | OpenAI 兼容 `reasoning_content`（部分中转用 `reasoning`）；Claude `content_block_delta` + `delta.type=="thinking_delta"` + `delta.thinking`；Gemini `parts[].thought==true` | 三个纯函数解析器分流（hotfix26）；流式与**非流式/降级路径都要提取**（hotfix35 补） |
| C5 | token 用量显示不出来 | 三家 usage 结构完全不同；流末 chunk 才带 | 三家 usage 解析器 + 请求带 `stream_options.include_usage` + 末片捕获（hotfix21） |
| C6 | 限流硬刚失败（连续 3 次 429） | 通用短退避（3s/10s）打不过限流窗口；流式异常丢掉了 HTTP 结构（认不出 429、拿不到 Retry-After） | 抛结构化 `LlmHttpException` + 429 专用退避序列 10s/30s/60s + 尊重 `Retry-After`（hotfix10） |
| C7 | 用户被问「你用的是哪家模型」 | 只适配了 3 家，新厂商要发版 | `ProviderCatalog` 数据驱动目录（30+ 家、五分组）+ **未收录 id 一律 OpenAI 兼容兜底** → 新增供应商零代码零发版（hotfix34） |

## 五、工程纪律（本项目固化的做法）

1. **每轮交付闭环**：改代码 → 干净编译（`--rerun-tasks`）→ 主 harness + **全套 18 个回归** → 提交（写清「现象/根因/修法/证据」）→ 推送 → 盯 CI 绿 → 下载产物做**二进制反验**（哈希比对 + versionName + dex 符号命中）→ 交付到 `/workspace`。
2. **零新增外部依赖**：能自写就自写（背景图解码、通知、动态取色、位图采样）。
3. **净室重写**：参照仓库只读思路、不抄代码。
4. **失败永不崩**：所有外部数据入口做降级（JSON 安全访问、分享降级、通知静默降级、背景图解码失败静默）。
5. **前向兼容**：落盘格式新增字段一律带默认值（老数据可读）。
6. **显示态与数据态分离**：后台任务不影响前台显示（owner 捕获 + 条件投影）。
7. **断言即文档**：harness 断言注释里写清「为什么这样断言」，产品变更时同步更新并注明。
