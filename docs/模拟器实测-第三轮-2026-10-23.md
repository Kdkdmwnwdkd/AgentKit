## 一、这轮测什么

前两轮把「正常路径」跑通了（多轮历史、工具循环、流式）。这轮专门打**异常路径与渲染边界**：

| 类别 | 场景 |
|---|---|
| 错误提示 | 401 / 429 / 500 / 网络断开 |
| 渲染边界 | 8000 字长文本 / 复杂 Markdown / 超长不换行串 |
| 互操作 | 停止生成 / ask_user / plan_propose / 危险工具审批 / 大工具结果 |
| 界面适配 | 横屏 / 深色模式 |

### 方法：把 mock 扩成「可编程故障注入器」

原来的 `/tmp/mock_llm2.py` 只支持 `calc` / `err401` / 回显。这轮扩成 `/tmp/mock_llm3.py`，按用户输入的关键词走不同分支：

| 触发词 | 行为 |
|---|---|
| `err401` / `err429` / `err500` | 返回对应 HTTP 错误 |
| `hang` | 永不响应（测超时） |
| `long` | 8000 字长回复（200 段） |
| `md` | 复杂 Markdown（代码块/表格/嵌套列表/引用/超长串） |
| `slow` | 慢速流式（100 片 × 0.4s ≈ 40s，测停止按钮） |
| `bigtool` | 调 `shell_run` 执行 `seq 1 2000`（测审批 + 大结果） |
| `askuser` | 调 `ask_user`（选项卡片） |
| `plan` | 调 `plan_propose` |
| `empty` | 空回复 |

> 判断分支只取「用户当前请求：」之后的文本——设备上下文里的「最近通知」会带上历史消息内容，用整段判断会被污染（第二轮踩过这个坑）。

## 二、发现的 10 个问题

### P0-1 发送消息后**不自动滚到底部**（最高频）

**现象**：发出消息后，界面停在原位置不动，底部出现「回到底部」箭头。用户看不到自己刚发的消息，也看不到回复。

**复现**：任意消息都会复现，这轮 8 次发送全部命中（`t1b.png` → `t1c.png`、`t2b.png` → `t2c.png`、`t7a.png` 等）。

**为什么是 P0**：429/500 会重试 3 次（约 30 秒）。这 30 秒里界面完全静止，用户以为卡死了，实际上在后台重试。**这是"看起来坏了"和"真的坏了"最容易被混淆的地方。**

**期望**：发送后立即滚到底；流式过程中跟随；用户主动上滑后才停止跟随（并给「回到底部」按钮）。

### P1-3 Markdown **表格不渲染**

**现象**：表格语法原样显示成文本：

```
| 列一 | 列二 | 列三 |
|---|---|---|
| 很长的单元格内容 AAAAAAAA | 短 | 中等长度内容 |
```

（`t6.png`）

**影响**：模型输出的对比表、参数表全部退化成竖线文本，可读性归零。这是最常见的输出格式之一。

---

### P1-4 代码块**横向裁切**，内容直接丢失（**已确认并修复**）

**现象**：代码块不折行、也不能横向滚动，超出宽度的部分被**裁掉**：

```kotlin
fun main() {
    val list = listOf(1, 2,        ← 后面的 3) 没了
    println(list.map { it *        ← 后面的 2 }) 没了
}
```

（`t6.png`）

**为什么严重**：不是"看不全"，是**内容消失**——用户/模型都意识不到少了一半，抄代码会抄错。

**根因（修复阶段确认）**：原实现是 `Box(fillMaxWidth().horizontalScroll(...)) { Text(softWrap = false) }`。
`fillMaxWidth` 先给 Box 定了死宽度，`horizontalScroll` 给子项的"无限约束"没起作用；
`softWrap = false` 又不换行，超出部分直接按 Clip 裁掉。
**关键是横滑完全没反应**（实测从屏幕右侧往左滑，位置纹丝不动），所以不是"需要滚动才能看全"，
而是真的看不见。

**修法**：改成 `softWrap = true` 让长行折行。取舍是「内容完整 > 行不折断」——
折行至少每个字符都在，横滑失效则整段内容消失。缩进由 monospace 的前导空格保留，
折行后仍能看出层级。

**验证**：同一段代码现在完整显示 `3)` 与 `2 })`（`g3.png`）。

### P1-5 401 错误卡片**过度展示**，且与 429/500 风格不一致

**现象**：401 卡片铺了 6 行：

```
🔑 API Key 无效或已过期（401）：
请到「模型」页检查 Key 是否正确、是否还有额度
端点：http://10.0.2.2:8080/v1/chat/completions
Key 指纹：len=11 head=sk- tail=key
服务端：{"error":{"message":"Incorrect API key provided","type":
"invalid_request_error","code":"invalid_api_key"}}
```

（`t1c.png`、`t1d.png`）

而同样价位的 429 / 500 都是一句话：

- `⏳ 请求过于频繁（429）：请稍后再试`
- `🔧 模型服务暂时不可用（服务端错误 500）：请稍后重试`

**问题**：
1. 服务端原始 JSON 对普通用户完全不可读，占了大半屏；
2. 三类错误风格不统一，401 明显更"吵"。

**期望**：统一成「一句人话 + 可选详情」。JSON 收进「详情」折叠区，或只在长按复制时给出。

---

### P1-6 401 的 URL **在单词中间硬折行**

**现象**：

```
http://10.0.2.2:8080/v1/chat/comple
tions
```

（`t1c.png`）

**期望**：优先在 `/` `.` `?` `&` 处断行；实在不行整段可横向滚动，至少别把单词劈开。

---

### P1-7 停止生成**丢弃已生成内容**，且文案与实际不符

**现象**：`slow` 场景流式到第 10+ 片时点停止，界面显示：

```
⬛ 已停止。已完成的历史保留，可基于它继续提问。
```

但**已生成的十几片内容一个字都没保留**（`t7d.png`）。

**问题**：文案说「已完成的历史保留」，用户理解成"我刚才看到的那些内容还在"，实际全丢了。这是**误导性文案**，比单纯丢内容更糟。

**期望**：保留已流式生成的部分（业界通行做法），或改成「已停止，本次回复未保留」。

---

### P2-8 危险操作审批 **10 秒自动拒绝偏短**，倒计时不显眼

**现象**：审批弹窗底部写着「10 秒后自动拒绝」，实测**连试 3 次、3 次都因超时被自动拒绝**（`t10d.png`、`t10g.png`）。第 4 次把「截图 → 点击」的间隔压到 4 秒才成功（`t10h.png`）。

**真实用户更慢**：要读命令内容（`seq 1 2000` 还好，复杂命令更长）、判断风险、再点按钮。10 秒对"危险操作确认"明显不够。

**附带问题**：倒计时只有一行 `labelSmall` 小字 + 2dp 进度条，视觉权重过低，用户根本注意不到自己只有 10 秒。

**期望**：延长到 30 秒；倒计时做成醒目元素（或按钮上的环形进度）；接近超时时震动/提示。

---

### P2-9 ask_user 选项**没有按钮外观**

**现象**：三个选项（Download / Temp / Cache）是纯文字，垂直排列、间距 84px，看起来像三个链接，不像可点选项；点击热区只有文字本身大小（`t8.png`）。

**期望**：给选项加按钮/卡片外观（至少整行可点 + 背景色），让"这是可以点的"一目了然。

---

### P2-10 错误卡片**没有「重试」入口**

**现象**：401 卡片下方只有「复制 / 重新生成 / 朗读 / ⋯」。

「重新生成」的语义是"重新生成这条回复"，不是"我改好 Key 了，再试一次"。用户照着提示去改 Key，回来后没有一个顺手的"重试"按钮（`t1d.png`）。

**期望**：401/网络类错误给一个「重试」按钮，直接重发上一条请求。

## 五、修复优先级建议

| 优先级 | 问题 | 理由 |
|---|---|---|
| **先修** | P0-1 不自动滚动、P0-2 大结果不折叠 | 这两个让"正常使用"直接失效，且修起来都不大 |

> 提醒：P2-8 的 10 秒超时是**安全相关的可配置项**，改的时候别把"自动拒绝"这个 fail-safe 本身去掉——那是危险操作的最后一道兜底。

### 7.3 顺带发现：模拟器里输入框点不动（**未修，环境问题可能性大**）

修复过程中出现"点输入框没反应、软键盘不弹"，一度怀疑是自己的改动。
**装回修复前的包（`/tmp/test4.apk`）复现同样现象** → 排除本次改动，判定为模拟器 IME 状态问题
（`input text` 依赖输入法连接，TCG 下唤起很慢）。
后来换包重启过程中键盘又能弹出，说明是**间歇性**的。

**没有修**，因为无法稳定复现、且旧包同样存在。下次遇到时的排查顺序：
① `adb shell dumpsys input_method` 看 IME 是否 connected；
② 点一次输入框后看 `files/drafts.json` 是否变化（变了说明聚焦成功）；
③ 仍不行就 `force-stop` 输入法再重启 App。
